# HiPER 式主屏与键盘设计

日期：2026-09-16
状态：待评审
依赖：Plan 1（主题 token 系统、表达式 AST、TeX 生成、`MathExpressionView`）已完成

## Goal

把 NekoCalc 的主界面换成 HiPER Calc Pro 的形态：**两行自然排版显示 + 单块 6 列密集键盘 + 侧边抽屉导航**。
工程工具箱（79 个工具）完整保留，退到次级入口。

这是**用户第一次能看见变化的阶段**。Plan 1 交付的是基础设施，主屏一行未改。

## 键盘：HiPER 布局，6 列，主键行与 SHIFT 标签行交替

已从官方截图与手册 PDF v12.0 逐像素解码。**核心机制：矮行不是按钮，是下面那行主键的 SHIFT 功能标签**——
`Σ`→SHIFT→`Π`、`∫dx`→SHIFT→`d/dx`、`sin`→SHIFT→`sin⁻¹`、`π`→SHIFT→`hyp`、`e`→SHIFT→`logₓy`。

**唯一例外**：`▸BIN` `▸OCT` `▸DEC` `▸HEX` 是**真按钮**（白色胶囊），被特意放进标签行。

```
[SHIFT][MENU][ ◀ ][ ▶ ][ ⌫ ][ AC ]
 ▸DRG   FSE   MTRX   Π   d/dx            ← SHIFT 标签行
[ DRG ][x⇔E][ [::] ][ Σ ][∫dx][ 📷 ]
 hyp   sin⁻¹  cos⁻¹  tan⁻¹  ∠   logₓy    ← SHIFT 标签行
[  π  ][ sin ][ cos ][ tan ][ i ][ e ]
 lim    x³    ∛x    ˣ√y   10ˣ   eˣ
[ x⁻¹ ][ x² ][ √x  ][ xʸ ][ log ][ ln ]
 STAT  a b/c   Y   HISTORY  M+   M−
[D°M'S][ d/c ][ X ][XY,M ][ MR ][x→M]
 CPLX    ∞          %        mod
[  7  ][  8  ][  9  ][   (    ][  )  ]
 n!    nCr   nPr   ▸BIN     ▸OCT
[  4  ][  5  ][  6  ][   ×    ][  ÷  ]
 CNST  CONV  abs   ▸DEC     ▸HEX
[  1  ][  2  ][  3  ][   +    ][  −  ]
OTHER  ran#  Ans   EXP SI    =,＜＞
[  0  ][  .  ][+/−][  EXP   ][  ✓  ]
```

**这从根上解决当前"函数页打不出数字、必须切页"的问题——数字键永远在位。**

### 落地范围：先做能落地的子集

HiPER 的键位里有相当一部分对应 NekoCalc 目前**没有的能力**（`MTRX` 矩阵、`Σ`/`Π` 求和求积、`∫dx`/`d/dx` 微积分、`lim` 极限、`i` 复数、`x⇔E` 结果格式切换、`[::]`、相机图像识别）。

**本阶段不实现这些能力**，但**键位格子要按 HiPER 的完整网格预留**：暂不可用的键渲染为**禁用态**（降饱和、不可点），而不是从网格中删除。理由是 HiPER 的价值一半在布局的肌肉记忆——删掉键会让网格错位，用户每次找键都要重新学。

具体哪些键启用、哪些禁用、哪些映射到 NekoCalc 现有但名称不同的能力，在实施计划里逐键列表定稿。

### SHIFT 的语义

- `SHIFT` 是**模态**键：点一次进入第二功能态，再点一次退出。
- 生效时，主键行按各自的 SHIFT 标签执行；标签行视觉高亮。
- 参考 HiPER 的设置项「按键标题风格（Casio / Sharp）」——**本阶段不做**，只实现一种（Casio 式，标签在上）。

## 显示区：两行

```
┌──────────────────────────────────────────┐
│ RAD            M 1  4 5 6        More... │  ← 状态行
│                                          │
│   π/2 × √((2/3)² − 2√cos(2π))            │  ← 表达式行
│                                          │
│                            =  iπ√14 / 6  │  ← 结果行（右对齐）
└──────────────────────────────────────────┘
  EXPR                    CPLX
```

- 表达式行用 Plan 1 的 `MathExpressionView`（自然排版 + 节点级点击定位 + 光标）
- 结果行同样自然排版。**但 Plan 1 的求值器只产出 `double`**，所以结果行暂时只能显示十进制数值——`iπ√14/6` 这类精确形式需要引擎，不在本阶段
- 状态行：角度模式（DEG/RAD）、记忆指示、显示格式指示、`More...` 按钮
- `More...` 本阶段接入现有能力（保存笔记、复制结果等）；矩阵/图像识别等禁用

**移除**：应用名标题行、`_padTabs()` 双标签页、常驻结果状态卡、常驻记忆条、底部三个操作按钮、主屏的 `SingleChildScrollView`（重写后**不得滚动**——当前有 211dp 溢出）。

## 导航：底部 tab → 侧边抽屉

- 主屏无底部导航
- 侧边抽屉（☰）提供 工具 / 笔记 / 历史 / 设置
- 工具页内部的分类、搜索、收藏、最近使用**全部保留不变**

## 主题接入

Plan 1 的三套主题（`roseCream` / `lavenderMist` / `peachSugar`，各含浅色与深色变体）在本阶段真正接到 UI 上：

- 所有键位取 `CalcTheme.keys` 的语义色（数字/运算符/函数/变量/模态/破坏性）
- 显示区取 `CalcTheme.display`
- **新增代码零硬编码颜色**

用户要求「提前留好多主题多颜色」——新增主题应当只是往 `CalcTheme` 加一个常量集，不需要改任何组件代码。本阶段要验证这一点成立：**加第四套主题时不触碰组件文件**。

## 架构

```
CalcTheme ──────────────┐
                        ↓
KeypadDefinition ──→ CalculatorKeypad ──→ 主屏
                        ↑                 ↑
MathExpressionView ─────┘                 │
CalculatorController ─────────────────────┘
（求值、历史、持久化、79 个工具全部不动）
```

新增模块：

| 模块 | 职责 |
|---|---|
| `KeypadDefinition` | 纯数据：行、列、键、SHIFT 标签、启用态、动作 |
| `CalculatorKeypad` | 按定义渲染网格；主键行 / 标签行 / 胶囊按钮三种视觉 |
| `CalculatorStatusBar` | 状态行：角度模式、记忆、显示格式、`More...` |
| `CalculatorDisplay` | 两行显示，装配 `MathExpressionView` |
| `AppDrawer` | 侧边抽屉导航 |

键盘是**纯数据驱动**的——键位表改了不需要改渲染代码。这同时为将来的「自定义键盘布局」留了路。

## 测试策略

- **单元**：`KeypadDefinition` 完整性（每个键有唯一 id、每个主键的 SHIFT 标签存在或显式声明为无、禁用键不产生动作）
- **widget**：主屏在 **320 / 360 / 412dp 下不溢出、不滚动**；数字键与函数键同时可见；SHIFT 按下后主键执行第二功能且标签高亮；禁用键不可点；点表达式任意位置进入编辑并定位；抽屉可达四个入口
- **主题**：把主题换成另两套后所有键位取到新色（遍历 `CalcTheme.all` 断言，不硬编码单一主题）
- **回归**：Plan 1 结束时的 686+ 测试全部保持通过

## 非目标

- 不实现 HiPER 有而 NekoCalc 无的能力（矩阵、微积分、复数、极限、结果格式切换、图像识别、RPN、Classic 模式）
- 不改数值引擎（仍是 `double`）
- 不做自定义键盘布局编辑（本阶段只做数据驱动，为用户自定义留路）
- 不删减 79 个工具
- 不改数据存储格式
- 不做 Casio/Sharp 按键标题风格切换

## 风险

| 项 | 处置 |
|---|---|
| 键位表庞大，逐键映射易错 | 以官方手册 PDF v12.0 与截图为唯一依据，逐键列表在实施计划中定稿并评审 |
| 禁用键让界面显得残缺 | 禁用态要有明确视觉语言（降饱和 + 不可点），而不是留白；并在 `More...` 或抽屉里给出现有能力的位置提示 |
| 键盘在 320dp 窄屏下过密 | 触控目标下限 48dp 与 6 列网格可能冲突；实施前先量 HiPER 在窄屏的取舍，必要时降为 5 列 |
| 结果行无法显示精确形式 | 明确接受；引擎在接口后，后续可替换 |
